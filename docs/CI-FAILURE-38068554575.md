# P2D 静止呈现测试：CI 失败与修复

2026-10-11。失败来源为 [iOS build / run 38068554575 / job 114261083484](https://github.com/itsCheney/Mikage-Next/actions/runs/38068554575/job/114261083484)。三仓版本为 Root `530e4168aa7e`、Runtime `13d3b9d2c58e`、Core `a0cfe5bd24c3`；本次只修改 Root 的测试、日志归档与说明，不提交、不推送。

## 已确认的失败事实

- runner：macOS 26.6.2 arm64，Xcode 26.6 / AppleClang 21，SDL3 3.4.16。
- `Build and test native Metal backend` 的 configure、Objective-C++ 编译和链接成功；三个 emitter/parser CTest 通过。
- tile 与 forced-compute 的 `metal-render-tests` 均失败于 `FAIL: unchanged frame never confirmed/skipped`。CTest 返回8，后续 MetalLayer、runtime framework、App device/simulator 构建全部未运行。
- 按测试调用顺序，NativeLayerInitializationTests 和 NativePendingFillTests 已返回，随后才进入失败的静止呈现用例。这是 macOS 上的子路径证据，不能标成整套原生或 iPhone 验收通过。
- 旧用例在12×8窗口中每100ms重新present，最多50次；没有先独立证明 runner 可提供真实显示回调。生产策略在16条未确认记录达到上限后保守禁止skip，因此这套等待方式本身可能使测试无法通过。旧日志缺少该阶段的确认/拒绝计数，不能据此断言一定是headless、某个回调未触发或生产去重错误。

## 修复

1. 静止present使用独立256×256可见窗口和单独CTest（tile/forced-compute），普通离屏Metal正确性测试继续独立运行。
2. 先请求真实presentation ticket并呈现一次；验证GPU读回成功，随后泵送并排空SDL事件、等待首次真实显示确认。等待期间不继续排队present，避免耗尽16条确认记录。
3. API不支持，或GPU未报错但首次真实显示确认在有界等待内不可得时，仅该独立用例返回77/`SKIP`，保持“显示路径待验”。GPU/probe明确失败仍判失败。
4. 一旦首次显示确认成功，后续不跳过、fresh ticket缺少显示证明、资源变化/失效/capture后错误跳过均保持失败断言；去重失败输出拒绝计数。
5. 抽取真实native测试正文并注入确定性时钟/显示边界，覆盖正常显示、首次无ACK、unsupported、command失败、probe失败、确认后的skip回归和fresh ticket失败。假边界测试不能代替原生显示验收。
6. Actions上传`Testing/Temporary/LastTest.log`和`LastTestsFailed.log`。原配置仅收集`build/*.log`，本次失败时没有保存CTest产物。

没有以command completion冒充display confirmation，也没有放宽生产present策略、16条上限或alpha gating。无ACK只允许首次能力探测返回待验；确认后的回归不会变成skip。

Windows从新目录配置Release构建，Backend CTest **4/4**；新增七种显示边界回归包含在backend测试内。native测试正文仍作为未链接C++ object编译。CLI在非Apple平台的独立呈现模式须返回77。

证据目录：`build/ci-failure-38068554575/`，包括原始job日志、新建portable构建和测试结果。修复后的Apple Actions尚未运行；必须在新提交上重新执行。普通native用例通过、独立present用例skip，应分别报告；App device/simulator与设备D2配对仍待验。
