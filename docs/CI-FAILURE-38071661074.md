# Runtime host 栈采样回调编译失败

2026-10-11。来源为 [run 38071661074 / job 114270126261](https://github.com/itsCheney/Mikage-Next/actions/runs/38071661074/job/114270126261)，Root `4c22081`、Runtime `b12af5d`、Core `e191359`。本次修复不提交、不推送。

## 失败与修复

`Build KRKR runtime framework` 在 `host/MikageKRKRRuntime.mm:597` 失败：

```text
error: no type named 'tjs_uint' in namespace 'TJS'; did you mean simply 'tjs_uint'?
```

CPU 栈采样回调把 `tjsTypes.h` 声明的全局类型误写成 `TJS::tjs_uint`。改为 `static_cast<tjs_uint>(bytes)`，保留实际位于 `TJS` 命名空间的 `TJSGetStackTraceUTF8` 调用。诊断接口、采样容量、执行顺序和线程限制均保持原有语义。

现有 Release 栈测试抽取了 host 的 tracer 生命周期代码，却未编译这个回调。本次将生产回调原文也纳入抽取，与真实 TJS VM、类型头和 `CPUFrameDiagnostics.h` 一起编译。运行检查覆盖 tracer 开关、活跃及空栈、异常/会话生命周期、非 VM 线程拒绝、512-byte 上限、小缓冲区、零 frame 和无效缓冲区。
