# EthornellRuntime host framework

Mikage Next runs BGI (Ethornell, BURIKO General Interpreter) games with [ethornell-rs](https://github.com/xmoezzz/ethornell-rs), a Rust reimplementation of the BGI engine, built as an embeddable iOS dynamic framework.

Pinned input:

- `Source/` submodule: `itsCheney/ethornell-rs`, branch `mikage`, based on upstream `main` (17280a6). The branch drops upstream's GitHub workflows (they built and published releases on every push to the fork), adds the MPL-2.0 license text the workspace declares, leaves out upstream's decompiled engine (`src/raw` and the C restored from it; nothing built used it) and two save files of a game, lets the save folder sit inside the game folder, and adds `ethornell_mikage_set_log_callback` and `ethornell_mikage_screen_size` (`crates/ethornell-mobile/src/mikage.rs`, `platform/ios/include/ethornell_mikage.h`). `MIKAGE.md` in the submodule lists the changes.

ethornell-rs isn't an SDL program. It renders with wgpu into the `CAMetalLayer` of a view, plays audio through kira (CoreAudio), decodes MPEG movies (video only) and BF_Movie image sequences in Rust, and plays SWF through ruffle. `scripts/build-ethornell-ios.sh` builds the `ethornell-mobile` crate (its host ABI, `ethornell_ios.h`) as a dynamic library for the device and Apple Silicon simulator, wraps each in `EthornellRuntime.framework` with the C headers and a module map, checks the exports, then creates `build/EthornellRuntime.xcframework`. It needs Rust with the `aarch64-apple-ios` and `aarch64-apple-ios-sim` targets and Java (ruffle_core's build script compiles its ActionScript library), nothing else from the other engines. It stays a framework of its own: siglus_rs and rfvp pin other wgpu and kira versions.

`App/Engine/BGISession.swift` gives the engine its own landscape window with a Metal-backed view, steps it from a display link and reuses the SDL engines' orientation, lifecycle and menu overlay code, as the Siglus and FVP sessions do. The engine draws all text with one face: PingFang (Traditional on Traditional Chinese devices), Hiragino Sans if that can't be loaded (`App/Engine/SystemFontExport.swift`). A touch is the left button; a long press is a right click, and so is the game menu's Back tile, which BGI games use for their menu and to close windows. Two fingers dragged up and down turn the mouse wheel, which opens and scrolls the backlog; the Backlog command is one wheel step up. Holding Skip holds Ctrl. A hardware keyboard sends Windows key codes. A three-finger touch opens the Mikage menu when that setting is on. The game's own message boxes and input dialogs show as alerts. Saves go to the game folder's `savedata` (the game's own files: `BGI.gdb`, `UserData/...`), which the engine hides from the game's resources. Going to the background pauses the game and its sounds. Leaving runs the game's own exit, which writes its global data; when the game asks "quit?" in a message box Mikage answers yes, and when it asks in a window of its own the player answers there (leaving again three seconds later quits without the game).

A game folder needs `system.arc`, which holds the boot program `ipl._bp`. The text encoding (Shift-JIS or GBK, for dialogue and names) comes from the game's page, or automatically: GBK when the folder's name marks a Chinese release (CHS, 汉化, GBK...), else Shift-JIS.

Known limits: auto mode, quick save and load, and the save and load screens have no engine-level hook, so those menu tiles stay off; movies play without sound, and WMV, MP4 and BMV movies don't play; the Mikage screenshot may come out black (the Metal layer is drawn outside UIKit); saves of the original Windows engine in the game folder are not imported. ethornell-rs follows one engine build (Tayutama 2) and has no per-version profiles, so older and newer BGI games may stop on calls it doesn't know yet.

ethornell-rs is MPL-2.0, which allows combining with Mikage's GPL-3.0-or-later. ruffle is MIT or Apache-2.0, its bundled Noto Sans subset OFL-1.1. The licenses are in the submodule and in Cargo's registry sources.
